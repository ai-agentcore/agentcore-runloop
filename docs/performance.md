## 历史测试：1C2G

2026-11-02 的初步测试中，**9 次请求有 5 次成功、4 次 HTTP 502**。成功请求的首个可见文本中位数为 **1.35 秒**，回答完成中位数为 **1.95 秒**。服务随后持续返回 502，因此停止继续探测；这些结果不能作为稳定性、并发容量或生产 SLA 的依据。

## 工作负载与成功标准

- 固定提示词：`Reply with exactly BENCH_OK. Do not use tools.`，期望输出 8 个字符。
- 请求使用 AG-UI，每次新建 `threadId`，并将相同值放入 `X-AgentCore-Session-ID`；`runId` 和消息 ID 也唯一。
- `tools: []`、`context: []`、`state: {}`、`forwardedProps: {}`；这不证明服务端未绑定 MCP 或 Skill，只表示本轮不要求使用工具。成功样本未出现工具调用事件。
- 成功须同时满足 HTTP 200、可解析的 SSE、`RUN_FINISHED`、无 `RUN_ERROR`，且最终答案等于 `BENCH_OK`。HTTP 200 本身不算成功。
- 没有自动重试；HTTP 错误计入总样本。时延统计仅使用成功样本，失败没有被当作低时延成功请求。

原计划后续串行 10 次、并发度 2 共 3 组。初始探测程序在串行失败后仍发出了首组两个并发请求，两次也均失败，随后停止；恢复检查单独执行。仓库中的复测脚本已改为任何失败后停止所有后续阶段，避免继续增加请求。

下表仅包含 **5 个成功请求**，单位为秒。P50 使用排序后样本的中位数；样本太少，不报告 P95/P99。

| 客户端观测指标 | 最小 | P50 | 最大 |
| --- | ---: | ---: | ---: |
| 首个 SSE 事件 | 0.032 | 0.044 | 0.266 |

计时从调用客户端 `fetch` 前开始，使用单调时钟。首个 SSE 事件可能只是 `RUN_STARTED`，不是模型答案。当前适配层先用 `THINKING_TEXT_MESSAGE_CONTENT` 输出候选活动文本，再在完成时提升为 `TEXT_MESSAGE_CONTENT` 最终答案；因此“首个可见文本”和“最终答案文本”是不同指标。它们也不等同于模型服务端 TTFT。活动与最终答案可能重复同一文本，不能将两者字符数相加估算吞吐。

[脱敏逐请求数据](performance-samples.json)保留所有成功与失败样本，不含服务地址、访问密钥、会话标识或原始响应正文。502 的根因未确认，不能据此断言 OOM、模型故障或平台限流。后续需结合网关日志、实例重启记录和模型调用日志定位。

## 复测

要求 Node.js 22+。下列变量仅由测量脚本读取，不改变 Agent 服务部署配置。将 URL 替换为自己的 HTTPS AG-UI 地址；API key 使用隐藏输入，不要直接写入命令历史或仓库。

```sh
export AGENTCORE_BENCHMARK_URL='https://<your-agent-endpoint>/ag-ui/agent'
printf 'API key: '
IFS= read -r -s AGENTCORE_BENCHMARK_API_KEY
printf '\n'
export AGENTCORE_BENCHMARK_API_KEY
AGENTCORE_BENCHMARK_REQUESTS=10 node scripts/benchmark-agui.mjs > /tmp/agentcore-benchmark.json
unset AGENTCORE_BENCHMARK_API_KEY
```

默认只做 10 次串行请求。确认服务稳定后，可在命令前增加 `AGENTCORE_BENCHMARK_PAIRS=3`，在串行阶段全部成功后执行 3 组并发度为 2 的请求。每个请求超时为 120 秒；脚本最多接受 30 次串行、3 组并发，失败即停止后续阶段并以非零状态退出。输出仅为指标，不输出密钥、URL 或原始响应正文。

脚本自检：`node --test scripts/benchmark-agui.test.mjs`。

## 下一步需要验证的工作负载

短回答只能验证基本链路。要补充真实业务效果，应分别测量文件读取与计算、Skill 加载、MCP 调用、文件发布，以及完整业务任务的正确率和耗时，记录实际输入与可核对的交付物。并发测试还需要明确实例数量和扩缩容策略；冷启动测试需要确认实例从未运行或确实重建。以上均尚未在本轮完成，不作为已验证案例展示。
